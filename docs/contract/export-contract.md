# 目标格式数据契约

本文是清理后数据的唯一目标格式契约，只规定三件事：数据包含什么、如何表示、如何存储。源数据的字段解释、转换方法和人工检查工具各有文档，不在本文范围内。

## 1. 概览

数据按 episode 组织，一个 episode 是一次连续的操作轨迹，包含四类内容：

| 内容 | 记录形式 | 定义 |
|---|---|---|
| 左、右臂实际 state | 各自的 EEF 绝对位姿 | 第 4 节 |
| 左、右夹爪实际 state | 各自的开合程度，`[0,1]` | 第 4 节 |
| RGB | 一个或多个相机的彩色视频，附逐帧时间戳 | 第 5 节 |
| instruction | 带起止时间的任务指令文本 | 第 6 节 |

不记录 action、关节状态、速度、深度、触觉、力或音频。

## 2. 存储结构

```text
dataset/
├── episodes.jsonl                  # 全部 episode 的元数据，见第 6 节
└── episodes/<episode_id>/
    ├── state/
    │   ├── left_eef.parquet
    │   ├── right_eef.parquet
    │   ├── left_gripper.parquet
    │   └── right_gripper.parquet
    └── rgb/
        ├── <camera_id>.mp4
        └── <camera_id>.parquet     # 该相机的逐帧索引
```

- 每个 episode 必须有全部四张 state 表和至少一个相机，每个相机的 MP4 与索引必须成对出现。
- `episodes.jsonl` 是唯一的元数据文件，所有 episode 级信息都集中在这里，不存在 per-episode JSON 文件。
- `episodes.jsonl` 中的全体 `episode_id` 与 `episodes/` 下的子目录一一对应。

## 3. 时间

同一 episode 的所有数据流共用一个 clock，各流按自己的原生节奏独立、异步记录。左右臂位姿、左右夹爪和各相机各有一条时间戳序列，频率和样本数不要求相同。

### 时间戳

每个样本带一个 `timestamp_ns`（`int64`，纳秒），表示该样本相对本 episode 共同时间原点的采样时刻。本契约中所有 `*_ns` 字段都是这个 clock 下的 `int64` 纳秒值。

### 共同时间原点

原点取本 episode 所有采样流（四路 state 和全部相机索引）首样本中最早的那个时刻。

- 各流不得分别以自己的首样本归零。
- instruction 不是采样流，不参与取原点。

### 规则

- **保留原生采样**：保留每个样本的原生采样时刻与间隔，不插值、不重采样、不补帧。
- **时间只来自时间戳**：不得用行号或 FPS 推算时间。行号只表示样本在本流内的顺序，不能用来跨流配对。
- **流内有序**：每个流按 `timestamp_ns` 非递减排列。
- **只在 episode 内可比**：不记录 clock 标识或绝对时刻，不承诺跨 episode 的时间对齐。

## 4. State

### 4.1 表结构

左臂、右臂、左夹爪、右夹爪各存为一张独立的 Parquet 表，每行是一个原生样本。

| 表 | 列 | Arrow 类型 | 含义 |
|---|---|---|---|
| `left_eef`、`right_eef` | `timestamp_ns` | `int64` | 采样时刻 |
| | `pose` | `fixed_size_list<float64, 12>`，不可空 | EEF 位姿，见 4.2 |
| `left_gripper`、`right_gripper` | `timestamp_ns` | `int64` | 采样时刻 |
| | `openness` | `float32` | 夹爪开合程度，见 4.5 |

列名与上表完全一致。`pose` 是单个定长列，不拆成多个标量列，也不用 struct。

### 4.2 pose 编码

`pose` 表示从 EEF 坐标系到参考坐标系的变换：

```text
p_reference = R @ p_eef + t
```

12 个分量的顺序固定为：

```text
[x, y, z, R00, R10, R20, R01, R11, R21, R02, R12, R22]
```

- `[x, y, z]` 即 `t`，是 EEF 原点在参考系中的位置，单位米。
- 后 9 个分量是旋转矩阵 `R`，按列优先展平，即依次为 `R` 的第一、二、三列。
- `R` 必须是正交矩阵，行列式为 `+1`。

位姿涉及两个坐标系：参考坐标系（4.3）和 EEF 坐标系（4.4）。本契约对前者只要求时不变，对后者完整规定原点与轴向。

### 4.3 参考坐标系

每条臂的位姿相对于一个在 episode 内时不变的参考坐标系，即该系相对外部世界保持恒定。

- 不得使用随时间运动的 link 作参考系，例如人形机器人的躯干 link。
- 不规定原点和轴向。各源可以沿用自己天然的固定系，例如机器人 base、odom 系或 episode 起始时刻的工具位姿。
- 左右臂不要求使用同一个参考系。臂间关系不在本契约的消费范围内，UMI 等源也无法提供。
- 不记录参考系的身份，因为它不影响本格式的消费。

> 为什么可以不规定参考系：下游由 state 导出的 delta 采用 body-frame 定义 `Δ = T_k⁻¹ · T_{k+1}`，参考系的原点与轴向在其中抵消。EEF 坐标系则不同，改变它的原点或轴向会改变 delta，所以 4.4 对它做了统一规定。

### 4.4 EEF 坐标系

EEF 坐标系的原点和轴向由本契约唯一固定，所有源、所有 episode 一致。

**原点**是夹爪安装接口的基准原点，即夹爪与腕部或工具座连接处的安装基准点。

- 具体的安装接口和基准点由模型或硬件声明。
- 同一安装接口的原点不随夹爪开合或指尖（fingertip）更换而改变。
- 指尖中心、工具工作端的 TCP 都不是 EEF 原点。

**轴向**：

| 轴 | 定义 |
|---|---|
| +X | 工具接近方向：从安装基准（法兰/腕部原点）指向工具工作端（TCP）。工具沿 +X 平动即靠近并接触工件 |
| +Z | 工具固有的「上」方向，即掌背（手背）法向；与 +X 正交，由模型或硬件声明 |
| +Y | `+Y = +Z × +X` |

接近方向和上方向都带正负，开合轴的正向因此由右手性唯一确定，不需要区分左右夹指。

**源的义务**：每个源用一个固定变换，把自己的原生工具系映射到上述 EEF 坐标系。这个变换以及安装接口基准原点的物理位置，记录在该源的源契约中。

### 4.5 openness

`openness` 是夹爪的实际开合程度，取值 `[0,1]`：`0` 为完全闭合，`1` 为完全张开。

- 归一化到 `[0,1]` 由源契约负责，导出时不做重标定。
- 转换脚本对三种取值的处理：范围内的值原样透传；有限的越界值可以裁剪到 `[0,1]`；非有限值报错。
- 各源具体的裁剪规则记录在该源的转换说明中。

## 5. RGB

每个相机存两个文件：一个 MP4 视频和一张逐帧 Parquet 索引。

### 视频

`<camera_id>.mp4` 采用 H.264 编码，不含音轨，帧序保留原生顺序。MP4 只承载帧图像，可以按固定帧率编码。

### 逐帧索引

`<camera_id>.parquet` 每行对应视频的一帧，与视频帧一一对应：

| 列 | 类型 | 含义 |
|---|---|---|
| `frame_index` | `int64` | 视频按显示顺序解码后的帧序号，从 0 开始 |
| `timestamp_ns` | `int64` | 该帧的采集时刻 |

帧的实际采集时间只以索引中的 `timestamp_ns` 为准，不得由 MP4 的容器时序或帧率推算。可变帧率也由此表达。

### camera_id

`camera_id` 是相机的文件名标识。

- **字符集**：只含小写 ASCII 字母、数字和下划线（`^[a-z0-9_]+$`），不含 `.`、`/` 或空格。
- **唯一性**：在一个 episode 内唯一。
- **一致性**：同一物理相机在该数据集的所有 episode 中使用同一个 `camera_id`；不要求跨数据集同名。
- **命名建议**：按视角取名，如 `top`、`left_wrist`、`right_wrist`；立体相机用 `top_left`、`top_right`。

## 6. 元数据：episodes.jsonl

`episodes.jsonl` 是 UTF-8 编码的 JSONL，每行一个 episode 对象，行顺序不限。下面列出的是全部契约字段；未列出的字段不属于契约，实现应当忽略。

### episode 对象

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `episode_id` | string | 是 | 等于 `episodes/<episode_id>/` 的目录名 |
| `cameras` | string[] | 是 | 本集包含的 `camera_id`，非空，与 `rgb/` 下的文件一一对应 |
| `instructions` | object[] | 是 | 指令区间列表，至少一条 |

### instructions

instruction 不是周期采样流，而是标注在共享 clock 上的区间：每条记录一段指令的生效时间。

| 字段 | 类型 | 含义 |
|---|---|---|
| `start_ns` | `int64` | 指令生效起点 |
| `end_ns` | `int64` | 指令生效终点，必须大于 `start_ns` |
| `text` | string | 任务指令文本，非空 UTF-8 |

- 区间按 `start_ns` 非递减排列，互不重叠。
- 整集只有一句指令时，该指令覆盖全轨迹：`start_ns = 0`（共同时间原点），`end_ns` 取本 episode 所有采样流（四路 state 和全部相机索引）中最大的 `timestamp_ns`。

### 示例

```json
{"episode_id":"episode_0001","cameras":["left_wrist"],"instructions":[{"start_ns":0,"end_ns":12000000000,"text":"pick up the cup"}]}
{"episode_id":"episode_0002","cameras":["left_wrist"],"instructions":[{"start_ns":0,"end_ns":8000000000,"text":"open the drawer"}]}
```
